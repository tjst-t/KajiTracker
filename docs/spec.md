# KajiTracker 仕様メモ

最終更新：2026-10-04

## 目的

週1回・月1回・半年に1回など、周期の違う家事を頭で覚えておかなくて済むようにする。
軸は **記録（Log）＋通知** の2つ。前回いつやったかを記録し、次にやる時期を通知する。

## 使う場面

- スマホと PC の両方で使う。
  - 普段の記録はスマホ。
  - 家事の登録・編集などは PC。
- 家族で共有する（妻、将来は子供も）。アカウントは1人ずつ作る。

## 用語

| 用語 | 意味 |
|---|---|
| User | 1人の利用者。パスキーでログインする。 |
| Family | 家事を共有するまとまり。1人が複数の Family に入れる。 |
| Chore（家事） | Family に属する、周期を持った家事。 |
| Log（記録） | ある家事を、誰がいつやったかの記録。 |
| 担当者 | 家事ごとに決められる User（任意）。 |

## 機能

### アカウントとログイン

- ログインはパスキー（WebAuthn）。パスワードは使わない。
- メールアドレスは必須にしない（子供もアカウントを作れるようにするため）。
- 1人がスマホと PC など複数の端末でログインできるようにする。仕組みは banto と同じ（参考：github.com/tjst-t/banto の docs/specs/v4-security.md「人のログイン」、packages/core/src/auth/）。

#### 最初の登録
- **新規登録は、招待の QR からだけできる。** だれでも登録できる入口は作らない。
- 招待の QR を開いた人は、その場でユーザー（表示名だけ）を作り、続けてパスキーを登録して、Family に入る。すでにアカウントを持っている人は、ログインして Family に入る。
- WebAuthn の user.id はユーザーごとに付ける。
- **最初の1人**（運用者）だけは、サーバ側のコマンド（wrangler 経由）で出す「1回だけ・10分だけの札」で入り、ユーザーを作ってパスキーを登録する。この札は API からは作れない。

#### 端末を足す（banto の「端末を追加」と同じ）
- ログイン済みの端末の設定画面で「端末を追加」を押すと、QR とリンクを出す（中身は同じ札。リンクにはコピーのボタン）。札は10分だけ有効、1回使えば終わり。
- 札は URL のフラグメント（`#login=<札>`）で運ぶ。アクセスログと Referer に残さないため。画面はまずフラグメントを URL から消し、それから API で引き換える。
- 使われたら、札を出した側の画面に「端末が入りました（おおよその端末名）」と知らせる。
- 入った端末で、続けて自分のパスキーを登録する。
- パスキーの同期（iCloud キーチェーンなど）やクロスデバイス認証も使えるが、それだけには頼らない。

#### パスキーとセッションの管理
- 1人が複数のパスキーを持てる。設定画面に一覧（名前・登録した日時・最後に使った日時）と1つずつ消す操作。名前は登録のときに付け、付けなければ User-Agent から大まかな端末名を入れる。
- 「ログイン中の端末」（セッション）の一覧も出し、1台ずつ締め出せる。パスキーとセッションは別々に管理する。
- 登録の設定：residentKey required、userVerification required、attestation none、登録済みは excludeCredentials で除く。署名回数は複製の検出に使わない（同期するパスキーは 0 を返すため）。
- サーバに持つのは credential id・公開鍵・署名回数・transports だけ。

#### セッション
- Cookie：`__Host-kaji-session`。HttpOnly・Secure・SameSite=Lax・Path=/、Domain は付けない。
- 値はランダムな 256 bit。サーバには SHA-256 のハッシュだけを置く。
- 期限は「最後に使ってから30日」。使っている間は延びる（最後に使った時刻の記録は1時間に1回まで、Cookie の出し直しは1日に1回まで）。
- CSRF 対策：Cookie で来た要求は独自のヘッダ（`X-Kaji-Client: 1`）が無ければ断る。Origin があれば画面のオリジンと照らす。
- 画面は iframe に入れさせない（frame-ancestors 'none'）。
- パスキーの検証では、clientDataJSON の origin を画面のオリジン1つに固定する。
- 認証の要らない口（札の引き換え・パスキーでの開始・新規登録）には、1分あたりの回数の上限を置く。

#### 大事な操作の前の本人確認（step-up）
- 端末を追加・パスキーの追加と削除・端末の締め出しの前には、その場でパスキーをもう一度通す。
- パスキーで入った直後の5分と、札で入った直後の10分は済んだものとして扱う。パスキーがまだ無いときは求めない。（足したばかりの端末がパスキーを登録できなくなるのを防ぐ。banto の実機で分かった落とし穴）

#### 全部の端末をなくしたとき
- 基本は、パスキーの同期（iCloud キーチェーン、Google パスワードマネージャー）に任せる。
- 加えて、**Family の管理者が、その Family のメンバーのために「ログインの札」を出せる**（端末を追加と同じ、1回だけ・10分。出す前に管理者は step-up）。その札で入った端末で、新しいパスキーを登録する。
  - 札を出したことは、本人にも残る形で記録する（本人の「ログイン中の端末」に「○○さんが出した札で入った」と出す）。
  - 管理者を両親2人にしておくと、管理者自身がなくしたときも回復できる。
- 回復コードは作らない。

### Family

- User は Family を作れる。作った人はその Family に入る。
- 1人が複数の Family に入れる。画面で Family を切り替える。
- **招待は QR コード**：管理者が招待の QR を出す → 相手の端末で読む → その端末でパスキーを作って（またはログインして）Family に入る。
  - 招待の QR は1回だけ使え、24時間で切れる。
- **役割は「管理者」と「メンバー」の2つ。** Family を作った人が管理者になる。
  - 管理者だけができること：招待、メンバーを外す、ほかの人を管理者にする・戻す、Family の削除。
  - 家事の登録・編集・記録は、メンバーも含め全員ができる。
- **抜ける・外す**：
  - だれでも自分で Family から抜けられる。ただし最後の管理者は、ほかにメンバーがいるあいだは抜けられない（先にだれかを管理者にする）。1人だけの Family から抜けると、Family の削除になる。
  - 抜けた・外された人の記録は残り、統計にもそのまま名前で出る。その人が担当だった家事は「担当なし」に戻る。
- **Family の削除**：管理者が、Family の名前を入力して確認したうえで削除する。家事と記録もすべて消える。

### 家事（Chore）

- 家事を登録する：名前、周期、担当者（任意）、通知の時刻（任意）。
- **周期は家事ごとに2種類から選ぶ。**
  1. **前回からの日数**：N日ごと。次の期限 ＝ 最後にやった日 ＋ N日。
     - 遅れたら、その分だけ次の期限も後ろにずれる。
     - 登録するときに、最初の期限を指定する。
  2. **カレンダーで固定**：決まった日。選べるパターンは次のとおり。
     - 毎週○曜日（複数の曜日も可。例：月・木）
     - 毎月第n○曜日（例：第1日曜日）
     - 毎月○日（月末も可）
     - 隔週・nか月ごと（例：2週間ごとの日曜日、3か月ごとの第1日曜日）
     - **遅れたとき**：次の予定日が来たら、前の回は「やらなかった」として打ち切る。遅れは新しい予定日から数え直す。打ち切った回は統計で未実施として数える。
- 日付の区切りは **日本時間（Asia/Tokyo）で固定**。

### 記録（Log）

- **ワンタップで「やった」を記録する。**
- 誰がやったかは、ログインしているアカウントで区別する。
- 記録は**取り消せる**。
- **過去の日付でさかのぼって記録できる**（付け忘れのため）。さかのぼった記録も、次の期限の計算に使う。

### 通知

- Web Push で送る。
- **期限の当日だけ**送る（事前通知・期限後の催促はしない）。
- 送る相手：担当者がいれば担当者だけ。いなければ Family 全員。
- **通知の時刻は人ごとに1つ**設定する（Family ごとには変えない）。
- **家事ごとに通知の時刻を指定することもできる。** 指定があれば、人の時刻より家事の時刻を優先して送る（例：ゴミ出しは朝7時、ほかはいつもの21時）。

### トップ画面

- アプリを開くと、**期限が来ている家事がいちばん上に、ひと目でわかるように**出る。
- 期限を過ぎた家事は、何日遅れているかを出す（例：「3日遅れ」）。

### 統計

思いつくものは入れていく方針。いまの候補：

- **分担**：誰が何回やったか（今月・全期間）、家事ごとの担当の偏り
- **期限の守り具合**：期限内にできた率、平均の遅れ日数
- **家事ごと**：実施履歴（カレンダー表示）、実際の平均間隔と設定した周期の差
- **全体**：週・月ごとの実施回数の推移、よく遅れる家事のランキング

## 技術

- Web アプリ。PWA にする（ホーム画面に置ける・通知を受けられる）。
- Cloudflare Workers にデプロイする。
- **本番のドメインは `kaji.tjstkm.net`**。パスキーの RP ID もこれにする。Workers のカスタムドメインとしてつなぐ（`tjstkm.net` が Cloudflare の DNS にある必要がある）。
- 構成（1つの Worker で画面と API の両方を配る）：
  - 言語：TypeScript
  - 画面：React ＋ Vite（`@cloudflare/vite-plugin`）。PWA は `vite-plugin-pwa`。
  - API：Hono
  - データ：D1（SQLite）。操作は Drizzle ORM。
  - パスキー：SimpleWebAuthn（`@simplewebauthn/server` / `@simplewebauthn/browser`）
  - Web Push：Web Crypto で動くライブラリ（`@block65/webcrypto-web-push` か PushForge）。Node.js 向けの `web-push` は Workers では動かない。
  - 当日の通知：Cron Triggers で15分ごとに Worker を起こし、送る時刻が来た人・家事に Web Push を送る。
  - テスト：Vitest ＋ `@cloudflare/vitest-pool-workers`
- ローカルでの開発とテスト：
  - `wrangler dev`（または Vite の開発サーバ）で、Worker・D1・Cron をローカルで動かせる。Cron は `--test-scheduled` で手動で起こせる。
  - PC のブラウザなら `localhost` で、パスキーも Service Worker も試せる。
  - スマホから試すには HTTPS の URL が要る（パスキーと PWA の決まり）。banto の公開の機能で開発サーバに URL を付けて試す。パスキーはドメインに結び付くので、その URL で作ったパスキーは本番では使えない。
- iPhone で通知を受けるには、ホーム画面に追加した PWA から通知を許可する必要がある（iOS 16.4 以降）。
